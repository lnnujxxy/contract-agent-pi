# 第 15–20 讲实现提炼

以下是读取第 15–20 讲正文后结合 pi-mono 官方 API 提炼的实现要求，不复刻课程正文。

## 15：Runtime

用统一模型层隔离 Provider 差异，用 Agent/AgentSession 管理消息、工具循环和事件。UI 只订阅事件，不直接耦合模型调用。自定义兼容端点可以复用现有 API 协议并覆盖 model id 与 base URL。

## 16：文档工具与结构化输出

文档解析、合同分类和最终报告都建模为统一工具。最终结果必须通过带 JSON Schema 的工具提交，避免从自由文本中猜测结构。

## 17：长合同与 Skill

Skill 放在 `.pi/skills/`，业务规则与工程代码分离，专业知识下沉到 references。长合同优先按章/条边界分块并保留重叠窗口；Agent 先加载 Skill，再逐块审查，报告阶段合并重复风险并保留原文证据。上下文接近窗口阈值时应缩小分块或压缩历史。

## 18：安全护栏

安全不只依赖提示词：先用工具白名单缩小攻击面，再在执行前校验路径、危险命令、外发域名和预算；敏感信息可用正则初筛、必要时再由轻量模型确认。工具执行后对内容脱敏，并通过事件记录工具名、成功/失败和拦截原因。

## 19：Web 接入

把 Agent Runtime 作为 UI 无关服务，后端用 SSE 推送文本增量、工具进度和报告事件。ChatPanel 用原生 Web Component 实现，发送前做权限预检，报告放进 sandbox iframe。浏览器不能直接获得任意文件系统访问权限，上传文件必须清洗名称、限制类型与大小。

## 20：TUI

使用 pi-tui 的 Text、Input、Container/TUI 等组件渲染状态和文本流，调用 `requestRender()` 触发差分重绘。Agent 事件映射为 UI 事件，从而避免 TUI 直接理解 Agent 内部状态。
